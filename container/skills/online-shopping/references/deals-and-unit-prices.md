# Deals and Unit Prices

Stores design promotions to look bigger than they are. Compare the cost per unit that the household will really use.

## Promotion types

Identify the type of each promotion before you compare it.

| Type | What the user gets | What to tell the user |
|---|---|---|
| Direct discount | A lower price at checkout. | The new price. |
| Loyalty-card credit | Credit for a future purchase. The price today does not change. | That the discount is credit, not a lower price today. |
| Multi-buy ("Leve 3 Pague 2", "2.ª unidade -50%") | A saving only at the required quantity. | The required quantity. Ask if the household needs that quantity. |
| Bigger pack | Possibly a lower unit price. | The unit price of each pack size. |
| Promotion on a different brand or size | A saving on a product that the user did not ask for. | The option. Do not change the item without a "yes". |

A large promotion is a bad deal if the household does not use the product before it expires.

## Suggested retail price

Some discounts start from a suggested retail price (PVPR or RRP). The supplier sets this price. On unknown own-label products, this price is often not a real price. A 70% discount from a high PVPR is possibly a normal price.

Tell the user if a discount starts from a PVPR. A known good product at an honest price can be better than a deep discount.

## Promotion dates and conditions

1. Read the dates of each promotion when you read the promotion.
2. Before you finish, read the price of each discounted item in the cart again. A promotion can end during the session.
3. If a price changed, tell the user the item and the amount.
4. Tell the user each promotion condition: minimum spend, card required, last day, one for each customer.
5. For a free-delivery code, tell the user the code, the minimum spend, and the last day.

## Unit prices

The unit price that the store shows is sometimes the wrong comparison. Calculate it again in these cases:

- **Compact or double-length packs.** "2 rolos = 4 rolos" is 4 standard rolls. Divide the price by the number of standard units.
- **Deposits on cans and bottles.** The store unit price can exclude the deposit. Add the deposit to get the checkout cost. Tell the user that the deposit comes back when they return the container.
- **Smaller packs.** A smaller pack can have a lower unit price. Always compare.
- **Same name, same price, different size.** Own-label products use one name for many sizes. Read the size on the product page.
- **Bone, shell, and drained weight.** The price per kg is not the price per kg of food. Give the comparison. If you estimate the waste, say that it is an estimate.

## Search problems

- The store search can show results for a different query. Look for a message such as "no results for X" above the results.
- Before you say that an item does not exist, try the brand name, the local name, a category page, and other spellings. Tell the user which terms you tried.
- Stock labels on result tiles can be wrong in both directions. The product page is correct.
- Stock can change with the delivery slot. If the user selects a slot later, check again the items with low stock.
